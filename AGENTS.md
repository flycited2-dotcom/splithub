# AGENTS.md — правила для агентов проекта SplitHub

Обязательные правила для любого ИИ-агента (включая **ChatGPT Codex**), работающего с
кодом splithub.ru. Цель: вести разработку мобильного приложения и интеграцию, **НЕ ломая
работающий сайт**.

## Что уже случилось (контекст)
02.06.2026 деплой мобильного бэкенда в прод добавил в **общий** `send.php` строгую проверку
каталога `validateCatalogItems()` — она требовала у каждого товара `items[].id` и точного
совпадения цены с `products.json`. А витрина `index.html` `id` не слала и имела старые цены →
**все заявки сайта падали** (`PRODUCT_UNAVAILABLE` / `CATALOG_CHANGED`). Параллельно Telegram
был заблокирован DPI РФ по IP. Сайт несколько часов не принимал заказы. Эти правила — чтобы
такое не повторилось.

## Архитектура: ИЗОЛЯЦИЯ (Вариант А)
Мобильное приложение и витрина сайта НЕ должны мешать друг другу.

1. **Мобильное приложение использует только свои эндпоинты** — `api/mobile.php`, `api/lib/*`,
   `api/push*.php`. **Не меняй поведение витрины** `send.php` и `index.html`.
2. **Не ломай сайт.** Любое изменение общих файлов (`send.php`, `index.html`, `products.json`,
   `config.php`, `db/init.php`) обязано сохранять текущий приём заявок. Это контракт.
3. **Валидация на сайте — не блокирующая.** Если каталог-проверка нужна и на витрине —
   применяй её только при наличии `id`; при расхождении цены **принимай** заказ и помечай его,
   но **не отвечай 409** и не теряй заявку клиента.

## Не удаляй и не ломай (уже в проде)
- `config.php`: `define('TG_FORCE_IP', ...)` — обход блокировки Telegram. Во **всех** curl к
  `api.telegram.org` обязана быть опция
  `CURLOPT_RESOLVE => ['api.telegram.org:443:'.TG_FORCE_IP]`. Без неё уведомления о заявках умрут.
- `send.php`: каталог-проверка обёрнута в `try/catch` и **не блокирует** заявку (fail-open).
- `products.js` — витрина, **275 активных** товаров с ценами владельца. Это **источник правды**
  каталога. `products.json` генерируется ИЗ него (см. `converter/`), а не наоборот. Не выгружай
  все 678 товаров (часть деактивирована по наличию у поставщика) и не меняй цены.

## Каталог — один источник
`products.js` (витрина) и `products.json` (серверная проверка) собираются из одного источника
(Excel → `converter/`) в одном деплое. Никогда не обновляй один без другого.

## Дисциплина деплоя
1. Не катай в прод половину интеграции (бэкенд без парного фронта).
2. Деплой парами (фронт + бэк) или за фиче-флагом.
3. После **каждого** деплоя — смоук-тест приёма заявки: POST на `send.php` телом, как шлёт
   живой `index.html` → ожидать `{"ok":true}`. Если не `ok` — откат.
4. Работай в ветке/PR, не правь прод мимо git.

## Git
- Источник правды кода сайта — ветка **`main`** (сведена с реальным продом 02.06.2026, коммит
  `61f3a35`). Начинай от неё.
- **Не распаковывай** полный `deploy.zip` конвертера на сервер — он пакует файлы рабочей папки и
  может затереть боевой код. Каталог деплой только через `converter/deploy.py`
  (заливает `products.js` + `products.json`).
