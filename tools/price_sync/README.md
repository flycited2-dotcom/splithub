# price_sync — сверка цен каталога с прайсами поставщиков

Пересчитывает цены и наличие каталога СплитХаб по прайсам поставщиков.
**Ничего не заливает на сайт.** Результат кладётся в `out/`, заливка — отдельно и вручную.

## Правила владельца

| Источник | Что берём | Наценка |
|---|---|---|
| трио.рус (парсинг сайта) | акционную цену, если акция идёт, иначе дилерскую | **+5%** |
| JAC b2b (`osatakti_mdv_b2b`) | «Вашу цену» из бланка заказа | **+10%** |
| Русклимат / Daichi / Бриз | опт из БД SplitHome, у Бриза — из его API | **+10%** |

Округление — вверх до ближайшего числа на `…90`: `275 → 290`, `15 692 → 15 790`,
`23 562 → 23 590`. Цена ровно на `…90` не меняется.

Наличие:

* трио: «есть» → `in_stock`; «нет» / «под заказ» / «ожидается» → `order_7` («Под заказ 7 дней»).
* JAC: крымский остаток > 0 → `in_stock`; есть на складе Москва (ОП АЯК-Крым) → `days_3_5`;
  иначе → `order_7`.
* SplitHome: склад «Симферополь» и остаток > 0 → `in_stock`; есть на других складах →
  `days_3_5`; иначе → `order_7`.

Опт-цена у поставщиков SplitHome лежит в разных местах: Daichi — `price_wholesale`,
Русклимат — `price_base`, а **у Бриза в БД РОЗНИЦА** (24 890 ₽ там, где опт 18 300 ₽).
Настоящий опт Бриза забирает `export_breez.ps1` из его `/leftoversnew/`. Нет выгрузки
Бриза — его позиции остаются без цены, наценка на розницу не накладывается.

Позиции, которых нет ни в одном прайсе, **не трогаются** — старая цена и наличие сохраняются,
и они перечислены в конце `out/price_diff.csv`.

## Запуск

```
cd <...>/splithub
python -m tools.price_sync.sync                      # боевой каталог с splithub.ru -> out/
python -m tools.price_sync.sync --catalog products.js  # взять локальный каталог
python -m tools.price_sync.sync --no-restore         # не возвращать THAICON / Mitsubishi Heavy
```

Выгрузки поставщиков (запрос выполняется НА СЕРВЕРЕ, пароли никуда не копируются):

```
powershell -ExecutionPolicy Bypass -File tools\price_sync\export_oasis.ps1   # каталог SplitHome
powershell -ExecutionPolicy Bypass -File tools\price_sync\export_breez.ps1   # опт-цены Бриза
```

### Ночной прогон на сервере

Сверка идёт на сервере SplitHome (`sprintbox-itp`, `/opt/splithub-price-sync`) по cron
каждую ночь в 04:00 МСК: `server/run_sync.sh` — выгрузки SplitHome и Бриза прямо там же,
пересчёт, карточки, сборка (фото новой карточки проверяется на splithub.ru), заливка
через предохранитель, итог в Telegram от бота остатков (ночью — без звука). Логи —
`/opt/splithub-price-sync/logs`.

Остатки JAC собирает компьютер: портал JAC серверным адресам отдаёт неполные данные.
`run_sync.ps1 -JacOnly` (задача планировщика, 20:00) запускает скрапер и отправляет
`jac_stock_latest.json` на сервер — в сверку и боту остатков. Не включали компьютер три
дня — сервер напомнит в Telegram, а JAC-позиции просто останутся как были.

После любой правки кода, реестров или прайса Техносистемса — выложить на сервер:

```
powershell -ExecutionPolicy Bypass -File tools\price_sync\push_to_server.ps1
```

Пока на сервере нет доступа к хостингу (`converter/config/deploy.json`), он считает
вхолостую, а сайт по-прежнему обновляет компьютер (`run_sync.ps1`, 04:00 и 20:00).
`push_to_server.ps1 -WithSecrets` кладёт доступ и переводит компьютер на `-JacOnly`.

```
powershell -ExecutionPolicy Bypass -File tools\price_sync\run_sync.ps1           # полный прогон здесь
powershell -ExecutionPolicy Bypass -File tools\price_sync\schedule_task.ps1      # планировщик (-JacOnly)
```

## Новые товары и сборка каталога

```
python -m tools.price_sync.new_cards   # заготовки карточек для товаров, которых нет на витрине
python -m tools.price_sync.merge       # свести с каталогом -> out/catalog/
```

Наполнение карточек (описание, преимущества, компрессор, фреон) лежит **данными** в
`card_content.json` по сериям — правится без кода. Чего в файле нет, то остаётся пустым:
пустое поле честнее правдоподобной выдумки, особенно по фреону. Новинка той же линейки,
что уже на витрине, наследует наполнение и фото у «родственника» — снимать нечего.

`merge` не пишет файлы, если проверка нашла хоть одну проблему: дубли id или sku, нулевую
цену, нехватку поля. Битый `products.json` ломает приём заявок, поэтому лучше не собрать,
чем собрать плохо. Позиции без цены («уточняйте» в прайсе) откладываются со списком причин.

## Расходники трио (`rashod_map.json`)

Шесть разделов трио, которые владелец прислал 25.09.2026 (медь, кронштейны, дренажные
насосы, лента, дренаж, фреон), ведутся реестром: sku карточки → раздел и точное название
строки прайса → цена и наличие каждый день, **наценка всегда 10%**. Там же текст карточки:
новые позиции `new_cards` создаёт сам (все, у которых у трио есть цена, — и «есть», и «нет»),
у выложенных `merge` обновляет текст. Строка пропала из прайса или цена 0,00 — карточка
остаётся с прежней ценой, но «Нет в наличии» (так ушёл R-22). Фото — в `assets/img/products`,
**на сервер их заливает не `publish`, а `deploy_file`** — новое фото сначала залить, потом каталог.

Медь в реестр не входит: трубу сопоставляет `consumables.py` — класс стенки (средняя /
толстая ГОСТ) по серии трио, из заводов ОАЭ / Узбекистан / Россия сначала то, что есть
на складе, потом самое дешёвое.

## Что на выходе

* `out/products.js` и `out/products.json` — готовый каталог, оба файла всегда согласованы.
* `out/price_diff.csv` — построчно: закупка, наценка, было → стало, дельта, смена наличия,
  плюс список позиций без источника.
* `out/rashod_candidates.csv` — расходники, где фасовка нашей карточки не совпадает с
  фасовкой поставщика («Болт 8-25» за 230 ₽ против 3,40 ₽/шт). Такие цены ставит человек.
* `out/oasis_stock.csv`, `out/breez_base.json` — сырые выгрузки поставщиков.
* `out/new_cards_draft.json` и `.csv` — карточки новых товаров.
* `out/catalog/products.js` и `products.json` — **итоговый каталог для заливки**.

## Важное про каталог

* Источник правды — **боевой** `products.js` с splithub.ru: он расходится с git
  (на проде 238 позиций, в репозитории 275). По умолчанию скрипт берёт именно боевой.
* THAICON (29) и Mitsubishi Heavy (5) на проде отсутствуют — скрипт возвращает их карточки
  из `products.js` репозитория, цену и наличие ставит из JAC.
* `splithub_master_template.xlsx` в репозитории содержит ЗАВЫШЕННЫЕ цены — как источник
  цен не использовать.
* Витрина поверх `products.js` мержит оверрайды админки по `sku`
  (`api/admin.php?action=products_overrides_public`). Для SKU с оверрайдом цены правка
  `products.js` на витрину не повлияет.
